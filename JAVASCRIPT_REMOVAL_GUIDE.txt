iBacolor JavaScript removal guide
=================================

The matching BEGIN/END comments in js/main.js mark the blocks below. These
markers only help locate code; they do not disable it. Removing a block removes
the feature it supports. Remove its matching startup call too, if one is listed.
Line ranges below refer to the current version of js/main.js. They can shift
after edits, so use the named BEGIN/END comments as the reliable markers.

Before removing anything
------------------------

- Back up the project first.
- Remove a whole matching block, not just its BEGIN/END comments.
- Test every page that uses the feature afterward.
- The current project is a frontend prototype. Account, request, report, and
  shared portal data are stored in this browser, not in MySQL.
- If replacing browser storage with PHP/MySQL, implement and test the PHP
  feature before removing its JavaScript block.

Blocks in js/main.js
--------------------

1. OPTIONAL BLOCK: Mobile navigation
   Lines: 6-32
   Code: initializeMobileNavigation()
   Startup call: line 1000
   Removing it disables the responsive menu open/close behavior and its Escape
   key handling.

2. OPTIONAL BLOCK: Barangay dropdowns
   Lines: 34-47
   Code: populateBarangaySelects()
   Startup call: line 1001
   Removing it leaves dropdowns marked with data-barangays unpopulated.
   The helper reads barangay names from MOCK_DATA.

3. OPTIONAL BLOCK: Service directory
   Lines: 49-157
   Code: initializeServiceDirectory()
   Startup call: line 1002
   Removing it disables the service listing, its search/category filters, and
   service links generated by JavaScript.

4. OPTIONAL BLOCK: Admin request filters
   Lines: 159-186
   Code: initializeRequestFilters()
   Startup call: line 1003
   Removing it disables keyword/status filtering on the admin requests table.
   It does not remove request submission or storage.

5. SHARED SUPPORT BLOCK: Date and time formatting
   Lines: 188-198
   Code: formatDateTime(value)
   No separate startup call.
   Do not remove while Community reports or Resident request pages remain:
   those features call this helper to format dates.

6. OPTIONAL BLOCK: Community reports
   Lines: 200-304
   Code: initializeReports()
   Startup call: line 1004
   Removing it disables resident report submission, browser storage, filtering,
   and report history display. It uses formatDateTime() and IBacolorStore.

7. OPTIONAL BLOCK: News filters
   Lines: 306-341
   Code: initializeNewsFilters()
   Startup call: line 1005
   Removing it disables the news category/date filters.

8. OPTIONAL BLOCK: Contact directory
   Lines: 343-436
   Code: renderDirectory()
   Startup call: line 1006
   Removing it disables JavaScript rendering of the office and contact
   directories.

9. OPTIONAL BLOCK: Registration, sign-in, and resident account settings
   Lines: 438-768
   Code: redirectToLogin(), initializeAccountAccess(), and hashPassword()
   Startup call: line 1007
   Removing it disables registration, sign-in, sign-out, resident account
   access checks, profile editing, password changes, notification preferences,
   and registration location capture. Do not remove hashPassword() alone:
   account registration, sign-in, and password changes depend on it.
   SESSION_KEY and ACCOUNTS_KEY at the top of main.js are used by this block
   and other resident features.

10. OPTIONAL BLOCK: Service request submission and resident request pages
    Lines: 770-964
    Code: initializeRequestSubmission(), initializeResidentRequests(),
    getResidentRequests(), initializeResidentDashboard(), and
    initializeResidentRequestDetails()
    Startup calls: lines 1008-1011
    getResidentRequests() has no startup call; other functions call it or are
    initialized directly.
    Removing this feature disables service request submission and the
    resident's request list, dashboard summary, and request details. It uses
    sessionStorage, IBacolorStore, MOCK_DATA, and formatDateTime().

11. OPTIONAL BLOCK: Generic demo form feedback
    Lines: 966-997
    Code: initializeFormFeedback()
    Startup call: line 1012
    Removing it disables the generic confirmation behavior for forms marked
    data-feedback-form. Specific registration/login/request/profile forms are
    explicitly excluded from this generic handler.

12. APPLICATION STARTUP BLOCK
    Lines: 999-1013
    Code: the initialize...() calls at the bottom of main.js.
    Do not remove this entire block while keeping any initialized feature:
    without its startup call, that feature's event handlers/rendering will not
    run. When removing a feature, remove only its corresponding call.

Related files
-------------

- js/data-store.js stores shared prototype records in localStorage. Reports
  and service requests use IBacolorStore from this file.
- js/mock-data.js supplies sample data and is used by several main.js blocks.
  Remove or replace it only after checking all pages that load it.
- js/navigation.js only marks the current navigation link.
- connection.php creates a PHP PDO connection; main.js does not call it.
  Browser JavaScript cannot directly connect to MySQL. A PHP backend/API is
  needed to use MySQL.
